# 变更提案：add-daily-credits-trend-chart

## 背景
每日统计页面（`DailyStatsPage`）目前仅以表格展示按日期降序排列的用量数据，用户需要逐行阅读数字才能判断近期 credits 消耗的涨跌趋势，不够直观。用户提供了参考截图（折线 + 面积填充 + 数据点数值标签的趋势图样式），要求在该页面顶部新增最近两周 credits 使用趋势图。

## 目标范围

**在范围内：**
- 在 `DailyStatsPage` 顶部（标题行下方、表格上方）新增一个折线 + 面积填充趋势图组件
- 统计最近 14 个自然日（含今天）的 `totalCredits`；缺失用量记录的日期按 0 填充，保证横轴连续
- 每个数据点上方展示具体数值标签，整体视觉风格参考截图（渐变面积填充、圆点标记、网格线、图例、标题）
- 纯前端手写 SVG 实现，不引入新的图表库依赖（当前 `admin-ui` 无任何图表库）
- 复用现有 `useDailyUsage()` hook 已获取的数据，不新增/修改后端接口

**不在范围内：**
- 不修改 `/api/admin/usage/daily` 接口及其响应结构
- 不支持自定义时间范围选择（固定最近两周）
- 不在 `DailyDetailPage`（单日详情页）新增图表
- 不引入任何新的 npm 图表库依赖

## 技术方案
- 新建纯展示组件 `admin-ui/src/components/daily-credits-trend-chart.tsx`，接收 `DailySummary[]` 作为 props，内部完成：取最近 14 天 → 按日期升序排列并补齐缺失日期为 0 → 计算 SVG 坐标 → 渲染图表
- **时间基准（消除时区歧义）**：`DailySummary.date` 字段语义为 UTC 日历日（`types/api.ts` 注释已注明）。"今天"通过 `new Date().toISOString().slice(0, 10)` 取当前 UTC 日期字符串，14 天序列通过 `Date.UTC(...)` 纯整数运算逐日回推并格式化为 `YYYY-MM-DD`，全程不经过浏览器本地时区转换；与 `data` 匹配时按字符串精确相等比较，不使用 `new Date(dateStr)` 做隐式时区解析。x 轴日期标签直接对 `YYYY-MM-DD` 字符串做子串裁剪取 `MM-DD` 展示，不对其调用 `new Date()` 二次解析，避免重新引入时区错位。此逻辑与页面现有 `formatDate`/`formatDateLabel` 两处仅用于*展示格式化*的时区处理（分别为 `+08:00` / `Z`）无关，互不影响，也不改动这两处既有代码
- 使用手写 SVG（`<path>` 面积填充 + 折线 + `<circle>` 数据点 + `<text>` 数值/日期标签 + 网格线 + 图例 + 标题），与仓库当前前端零图表库依赖的现状保持一致
- `DailyStatsPage` 在标题行与表格之间引入该组件，传入 `useDailyUsage()` 已获取的 `data`
- 数据加载中或为空时，图表区域不渲染（沿用页面已有的 loading/empty 判断，不重复请求）

## 预期影响
- 仅前端展示层新增，不影响任何现有 API 契约、数据结构或后端逻辑
- 对已有表格渲染逻辑无侵入性修改，只是在其上方插入新组件
- 手写 SVG 不新增 bundle 体积（对比引入 recharts 等库的数十 KB 增量）

## 风险
- 手写 SVG 布局在窄屏下可能出现数值标签重叠 —— 通过限制字号（9-11px）与点间距自适应缓解，不做逐像素防重叠碰撞检测
- 若近 14 天内 credits 数值差异极小甚至全部为 0（曲线接近水平线），y 轴网格线的自适应计算需覆盖"最大值为 0"边界，此时退化为固定网格（如 0/1/2/3）避免除零
- 时区错位风险已消除：技术方案已明确日期序列生成/匹配与 x 轴标签渲染均使用 UTC 字符串运算，不经过浏览器本地时区转换
