# 设计说明：redesign-remaining-pages-ui

## 上下文

上一变更（`redesign-account-management-ui`）已在 `index.css` + `tailwind.config.js` 建立完整令牌双轨制（shadcn HSL 三元组重映射 + 设计稿原生 hex/rgba 以 `var(--x)` 暴露），并在账号管理页落地了 `.metric` / `.panel` / `.tscroll` / `.tag` / `.sw` / `.cb` / `.pager` / `.toolbar` / `.actionbar` / `.btn` / `.iconbtn` / `.tip` / `.delta` / `.acct` / `.quota` 等组件的 Tailwind 实现。

本变更需要在此基础上落地 6 个有稿页面 + 6 个无稿页面，并新增 7 组设计稿组件类：`.conn*`（连接卡）、`.chart-*` + `.plot-*`（图表）、`.logpanel` + `.logrow` + `.lv`（日志流）、`.tl-*` + `.rel-*`（时间线）、`.set-*`（设置分区）、`.mult-bar`（倍率条）、`.field`（表单字段）。

约束：零后端改动、不新增运行时依赖、Tailwind 3.4、无测试基建（验证仅 `tsc --noEmit` + `npm run build`）。

## 目标 / 非目标

**目标**

- 12 个页面的视觉语言完全统一，任意两页之间不存在页头结构或组件形态断层
- 所有现有交互能力零丢失
- 新增结构可被 Tailwind 原子类表达的部分不落入 `index.css`，保持样式可就地阅读

**非目标**

- 不追求与设计稿逐像素一致的「理想态数据」—— 后端无字段的展示位按 proposal 的降级表处理
- 不引入图表库、动画库、表单库
- 不重构数据层（`hooks/use-credentials.ts` 等仅在需要新 selector 时增补，不改请求结构）

## 决策

### 决策 1：页头提取为共享组件 `PageHead`，而非每页重复手写

12 个页面都需要「面包屑 + 19px 标题 + 同基线副标题 + 右侧动作区」。账号管理页当前是在 `dashboard.tsx:1082-1105` 内联手写的。

**决策**：新建 `components/page-head.tsx`，签名为
`{ crumb: string[]; title: string; note?: ReactNode; actions?: ReactNode; onBack?: () => void }`。
B 组详情页通过 `onBack` 渲染返回按钮（账号管理页不传）。`dashboard.tsx` 内联页头同步替换为该组件。

**理由**：12 处重复 24 行结构 = 288 行冗余；面包屑末级 `aria-hidden` 与 h1 同文案的读屏处理只需维护一份。

**代价**：动了账号管理页的页头（属上一变更范围），需在 CR 中明确此处为有意改动。

### 决策 2：Tailwind 原子类优先，仅三类情况落 `index.css`

**落 `index.css` 的白名单**：

1. `.logstream` 的等宽日志行 —— 需要 `font-variant-ligatures: none` + 精确 `11.5px/1.55` 行高，且行内 `<b>` 高亮需后代选择器
2. 图表绘图层 `.plot-grid` / `.plot-band` / `.plot-y` / `.plot-x` —— 依赖百分比绝对定位与 `::before` 基线，Tailwind 任意值表达后可读性显著劣于 CSS
3. `.tl-main` 时间线竖线 —— `::before` 贯穿伪元素 + 节点圆点定位

**其余全部用 Tailwind 原子类**，包括 `.conn` / `.set-*` / `.field` / `.mult-bar` / `.rel-*` / `.tag` 变体。

**理由**：与上一变更保持同一策略（账号管理页除 `@layer base` 令牌外零自定义类），样式可就地阅读、不产生「改了类名但 CSS 还在」的死代码。

### 决策 3：B 组无稿页面的推导基准限定为 A 组已实现组件，不自创

**决策**：B 组 6 页只允许使用以下已实现组件：`PageHead`（带 `onBack`）、`.metric` 指标卡、`.panel` + `.tscroll` 表格、`.panel-foot`、`.tag`、`.btn` / `.iconbtn`、`.toolbar`、`.pager`、`.field`。禁止为 B 组新增任何组件类。

**理由**：无像素基准的自由发挥必然产生新的不一致，且无法在 CR 中判定对错。限定组件池后，B 组的正确性可归约为「是否只用了白名单组件」这一可验证条件。

### 决策 4：设置页按「后端支撑」裁剪，不渲染占位

设计稿设置页有 5 分区 20 项，现有后端仅支撑 3 项。

**候选方案**：
- (a) 渲染全部 20 项，无支撑项禁用并标「暂不支持」
- (b) 只渲染有支撑项，无支撑分区整体不渲染 ← **采纳**

**理由**：(a) 会让管理员误以为功能存在只是被禁用，产生错误预期，且 17 个禁用行会淹没 3 个可用项。(b) 的代价是与设计稿 PNG 差异明显，通过在 `spec.md` 登记「不渲染项」清单消解。

**落地形态**：保留「服务」「认证与安全」「界面」三个分区标题（各有至少 1 项支撑），删除「账号池与调度」分区标题但把其唯一有支撑的「选择策略」（`loadBalancingMode`）上移到「服务」分区，删除「危险区」整个分区。

### 决策 5：图表用内联 SVG + 百分比定位，不引入图表库

**决策**：`daily-credits-trend-chart.tsx` 重写为设计稿形态：`<svg viewBox="0 0 100 100" preserveAspectRatio="none">` 承载面积 + 折线两条 `<path>`，折线用 `vector-effect="non-scaling-stroke"` 保证线宽不被 X/Y 非等比缩放拉伸；数据点、峰值标注、零消耗区间带、Y 轴刻度、X 轴日期标签全部用百分比绝对定位的普通元素叠在 SVG 上层。

**理由**：设计稿本身就是这个实现，直接对稿；引入 recharts/echarts 会新增 100 kB+ 依赖且难以复刻零消耗区间带。

**边界守卫**（`spec.md` 有对应场景）：
- 数据点数 `< 2` → 不渲染折线与面积，只渲染单个数据点或空状态
- 全部值为 0 → Y 轴上界取 1（避免 `value / max` 除零），折线贴底
- 峰值标注仅在峰值 > 0 时渲染

### 决策 6：对话框只改字段视觉，不动结构与提交逻辑

**决策**：5 个对话框内的 `<Input>` 替换为设计稿 `.field` 视觉（通过改 `ui/input.tsx` 的基础样式实现，不逐个改对话框），布局 `space-y-*` / `grid-cols-2` 与 `handleSubmit` 逻辑完全不动。带单位的字段（如秒 / % / RPM）用 `.field` 的 `u` 后缀 span 包裹。

**理由**：设计稿无 dialog 原型，重排布局是无基准的返工风险；改 `ui/input.tsx` 一处即覆盖全部 5 个对话框 + 编辑对话框 + 登录页。

### 决策 7：每页独立任务 + 独立增量 CR，不批量推进

**决策**：`tasks.md` 按「共享层 → A 组 6 页 → B 组 6 页 → 对话框 → 收尾验证」拆为 18 个任务，每个任务单独 `Edit tasks.md` 勾选并跑一次增量 CR（沿用 `00-change-gate.md` 的分片规则：≤300 行且 ≤1 文件 → `SHARDS=1`）。

**理由**：单任务改动量 100~300 行，正好落在 CR 单分片的有效审查区间；12 页合并成一次 CR 会超 3000 行，必然漏审。

**两个页面被拆为各 2 个任务**：`api-keys-panel.tsx`（1094 行）与 `log-viewer-page.tsx`（420 行）若整页一个任务，预估产出分别约 500 行与 400 行，会突破本决策自身的「≤300 行单分片有效区间」并超出 `tasks.md`「每任务不超过 2 小时」的粒度基准。故各拆为「页头 + 指标卡 + 工具条」与「数据主体 + 页脚 + 能力核对」两个任务，各自独立 CR。其余 10 页单任务产出均 ≤300 行，不拆。

### 决策 8：指标卡与工具条视觉件提取为共享原语（实施中追加）

决策 3 把 `.metric` 指标卡与 `.toolbar` 列为「已实现、可复用」的组件池，但实际实现是 `account-metrics.tsx` 与 `account-toolbar.tsx` 的**文件内私有函数，未导出**。T3（API Keys）、T6（每日统计）、T8（支持模型）、T10（实时日志）四个任务都需要同一批件：4 段式指标条、`.m-val` 主值行、环形图、sparkline、`.delta` 环比徽标、`.search` 搜索框（含 ⌘K 劫持与平台判定）、`.seg` 分段筛选、「更新于 X 前」。

**候选方案**：
- (a) 每页各自实现 —— 约 120 行 × 4 页 ≈ 480 行重复，任意令牌调整需改 5 处
- (b) 提取共享原语 ← **采纳**

**落地形态**：新建 `components/metrics.tsx`（`MetricsBar` / `Metric` / `MetricValue` / `MetricAside` / `MetricFoot` / `FootSep` / `Ring` / `Sparkline` / `Delta`）与 `components/toolbar.tsx`（`Toolbar` / `SearchBox` / `Segmented` / `UpdatedAgo`），两者只承载**纯展示**，不含任何领域字段；`account-metrics.tsx` 与 `account-toolbar.tsx` 改为消费方，保留各自的领域装配与 `remainingTone()` / `SEGMENTS` / `AccountStatusFilter`。

**理由**：与决策 1（提取 `PageHead`）同构 —— 12 页共用结构不应有 12 份实现；且决策 2 的「样式单点可读」在多页复制下必然失效。

**代价**：动 2 个上一变更已验收的文件。约束为「只搬不改」：className 串逐字保留，不调整任何令牌值，视觉输出必须零变化，由 T2.5 的独立 CR 逐项核对。

**语义参数化**：`Ring` 新增 `tone` 参数（`stroke-*` 类名）。账号管理页的环形图表达「剩余百分比」（越高越好，60/30 阈值切 ok/warn/danger），API Keys 页表达「配额占用」（越高越坏，设计稿恒 warn），二者语义相反，故阈值函数留在调用方而非原语内。

### 决策 9：模型页两处指标按现有字段重定义语义，而非渲染恒定占位（实施中追加）

`spec.md` 原定第 3 张指标卡为「默认模型」、`proposal.md` 原定状态列恒为「可用」。T8 实施时核对 `types/api.ts` 的 `ModelItem`（`id` / `object` / `created` / `owned_by` / `display_name` / `type` / `max_tokens` / `rate_multiplier?`）确认：无任何字段可表达「默认模型」；状态列若恒为「可用」则零信息量。

**候选方案**：
- (a) 按原文字面渲染 —— 指标卡显示「—」，状态列 100% 同值，两处均为占位噪音
- (b) 用现有字段重定义语义 ← **采纳**

**落地形态**：第 3 张指标卡改为「倍率数据覆盖」（`syncedCount` / 总数 + 环形图）；状态列改为 `RATE_STATUS` 两态「已同步」/「倍率缺失」，判据为 `rate_multiplier` 是否为 `null`（后端回退本地静态表时该字段全空）。

**理由**：与决策 4（设置页按后端支撑裁剪、不渲染占位）同构 —— 数据缺口应转化为现有字段能表达的真实信息，而非保留空壳展示位。

**代价**：`spec.md`「4 张指标卡渲染」场景与 `proposal.md` 降级表需同步修订（已于 T17 收尾 CR 后回写）。「默认模型」这一缺口在阶段 1 起草时漏登记，属 proposal 完整性缺陷，由 T17 三维 CR 分片 3 发现。

## 风险 / 权衡

| 风险 | 权衡 |
|---|---|
| 决策 1 动了上一变更已完成的账号管理页页头 | 接受。收益（消除 288 行冗余）大于代价（一处已验收代码的受控改动），且 diff 可控在 24 行内 |
| 决策 2 的白名单可能在实施中被侵蚀（「这个也用 CSS 更方便」） | 白名单是封闭的 3 条；实施中若需第 4 条，须先在 `design.md` 追加决策并说明为何 Tailwind 无法表达 |
| 决策 4 让设置页与 PNG 对稿图差异最大，人工验收时最容易被判为「没做完」 | 通过 `spec.md` 的不渲染清单 + 验收标准显式声明消解 |
| 决策 5 的手写 SVG 在极端数据下路径退化 | 已在 `spec.md` 登记 3 个边界场景；实施时守卫代码需被 CR 明确核对 |
| 决策 6 改 `ui/input.tsx` 会影响全部 8 处输入框（含已验收的编辑对话框、登录页） | 接受。这正是统一视觉语言的目的；风险是登录页输入框尺寸变化，在 T15 登录页任务中一并核对 |
| 决策 8 动了上一变更已验收的 `account-metrics.tsx` / `account-toolbar.tsx` | 接受。约束为「只搬不改」（className 逐字保留、零令牌调整），收益是消除 480 行跨页重复；风险由 T2.5 独立 CR 的「视觉输出零变化」核对项兜底 |
| 17 个实施任务 × 每任务 1 次 CR = 17 次 sub-agent 调用，耗时长 | 接受。上一变更已验证单分片 CR 约 450s，总计约 2 小时纯 CR 时间，换取每任务可独立回滚 |
