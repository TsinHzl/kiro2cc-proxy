## 新增需求

### 需求：全局语言切换

Admin 控制台需要提供一个全局中/英文切换入口，切换后覆盖全部 Admin 页面的界面文案渲染，并持久化用户的语言偏好。

#### 场景：用户在设置页面切换语言

- **WHEN** 用户在"设置"页面的"语言"分组中选择中文或 English
- **THEN** 当前会话内全部已挂载的 Admin 页面（导航、账号管理、API Keys、每日统计、日志、支持模型、更新日志、登录页、设置页自身）的界面文案立即切换为对应语言渲染，无需刷新页面

#### 场景：刷新页面后语言偏好保持

- **WHEN** 用户已切换过语言（如切换为 English）后刷新浏览器或重新打开 Admin 控制台
- **THEN** 页面加载时读取 `localStorage` 中保存的语言偏好并以该语言渲染，无需用户重新选择

#### 场景：首次访问无持久化记录

- **WHEN** 用户首次访问 Admin 控制台，`localStorage` 中不存在语言偏好记录
- **THEN** 页面默认以中文渲染，不进行浏览器 `Accept-Language` 自动检测

### 需求：更新日志页面语言跟随全局设置

更新日志页面不再维护独立的语言切换状态，改为跟随全局语言设置渲染。

#### 场景：全局语言切换后更新日志页面文案联动

- **WHEN** 用户在设置页面将全局语言切换为 English，随后访问"更新日志"页面
- **THEN** 页面内版本分组标题与条目文案渲染为后端返回的 `en` 字段内容；版本号、日期等非文案字段不受影响；页面不再显示原有的页面内独立语言切换按钮

### 需求：设置页面 iOS 风格列表布局

设置页面的视觉呈现从并排卡片网格改为 iOS Tableview 风格的分组列表。

#### 场景：设置页面分组列表渲染

- **WHEN** 用户打开"设置"页面
- **THEN** 页面以分组列表形式呈现（认证密钥、负载均衡、语言三个分组），每个分组含灰色小字分组标题 + 圆角容器；容器内各设置项以行的形式排列，行与行之间以分隔线区分，不再使用原先并排的两栏卡片网格布局；原有的认证密钥编辑/保存/取消交互与负载均衡模式切换交互功能保持不变
