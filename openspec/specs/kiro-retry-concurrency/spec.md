## Purpose

定义 Kiro API 客户端在请求重试/退避过程中对并发资源（全局与单账号 semaphore）的持有与释放行为，确保限流退避期间不会无谓占用其他并发请求所需的账号级并发槽位。

## Requirements

### Requirement: 退避等待期间释放账号级并发槽位
系统在因 429 / 5xx / 网络发送失败等原因进入指数退避等待前，SHALL 释放当前账号级并发 semaphore（`_cred_permit`），使该账号的其他并发请求可以使用该槽位，而不必等待本次退避结束。

#### Scenario: 429 限流触发退避
- **GIVEN** 某账号当前并发请求数未达到单账号并发上限
- **WHEN** 该账号收到上游 429 响应且剩余重试次数 > 0
- **THEN** 系统在调用 `sleep()` 进入退避等待之前释放该账号的并发槽位
- **AND** 该账号的其他等待中请求可以在此期间获取到该槽位

#### Scenario: 5xx / 网络发送失败触发退避
- **GIVEN** 请求发送失败，或收到 408/5xx 响应，且剩余重试次数 > 0
- **WHEN** 系统计算退避时长并调用 `sleep()`
- **THEN** 系统在调用 `sleep()` 之前释放该账号的并发槽位

#### Scenario: 端点全部被限流触发退避
- **GIVEN** 该账号所有可用端点均处于限流冷却状态
- **WHEN** 系统决定等待后重试，且剩余重试次数 > 0
- **THEN** 系统在调用 `sleep()` 之前释放该账号的并发槽位

#### Scenario: RPM 硬限制等待
- **GIVEN** 某账号当前请求速率（RPM）已达到配置上限
- **WHEN** 系统需要等待下一个 RPM slot 释放
- **THEN** 系统在执行该等待之前不获取该账号的并发槽位（即 RPM 等待与并发槛位互不占用）
