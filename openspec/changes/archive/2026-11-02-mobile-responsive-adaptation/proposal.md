# 变更提案：mobile-responsive-adaptation

## 背景
当前 `web-ui/admin-ui` 与 `web-ui/user-ui` 按桌面端宽屏视口设计：
- `admin-ui` 左侧边栏固定占宽 `232px`（折叠态 `64px`），主内容区固定 `ml-[232px] px-9 py-7`，在手机屏幕（如 375px 宽度）下主内容区仅剩约 143px 可用宽度；
- `MetricsBar` 采用内联 `gridTemplateColumns: repeat(N, minmax(0, 1fr))`（3 至 8 列不等），在手机端多列挤压导致数字与标签严重重叠；
- 多列表格（账号表、API Key 表、使用日志表、模型列表等）、固定宽度搜索框（`w-[232px]`）、设置项输入行（`w-[290px]`）及实时日志 `.tgt` 列（`min-width: 250px`）在窄屏下发生横向溢出或内容截断；
- `user-ui` 仪表盘与使用日志页的 4 列指标条、双列时间卡片与宽表格在手机端同样存在挤压与无法横向滚动的问题。

需要以**最小代码改动**的方式完成 `admin-ui` 与 `user-ui` 的手机尺寸响应式适配，且严格保证网页端（`>=1024px`）零视觉与功能回归。

## 目标范围
**在范围内：**
- `admin-ui` 导航与主框架手机端适配（`<768px` 下隐藏常驻占位侧栏，提供移动端顶部导航栏与抽屉式侧边栏 + 遮罩层，主内容区去除左偏移并缩减内边距）
- `admin-ui` 全局与原语级手机端适配（`MetricsBar` 窄屏自动折行成 2 列网格、表格容器支持横向平滑滚动、`SearchBox`/`Segmented` 窄屏自适应、`SettingsPanel` 设置行换行与输入框限宽、`LogViewerPage` 日志行目标列缩窄、`DocsPage`/`ChangelogPage` 吸顶负边距适配）
- `user-ui` 手机端响应式适配（仪表盘与使用日志页容器边距优化、激活/到期时间窄屏单列堆叠、指标条窄屏 2 列折叠、日志表横向滚动）

**不在范围内：**
- 网页端（`>=1024px`）任何布局、字号、间距、交互逻辑或组件结构的修改
- 后端 Rust 接口或数据模型的修改
- 将桌面端数据表格重写为移动端独立卡片视图组件

## 技术方案
1. **断点隔离原则**：所有新增样式与布局分支严格限定在 Tailwind `max-md:`（`<768px`）或 CSS `@media (max-width: 767px)` 媒体查询内，桌面端 className 与 DOM 行为保持原样。
2. **`admin-ui` 抽屉式侧边栏**：在 `dashboard.tsx` 增加 `mobileNavOpen` 状态，手机端顶部渲染 `md:hidden` 固定顶栏（汉堡按钮 + 品牌标识），`Sidebar` 在 `max-md:` 下通过 `translate-x` 切换抽屉显隐并附带遮罩层，点击导航项后自动收起。
3. **CSS 集中覆写多列指标条与表格滚动**：在 `admin-ui/src/index.css` 与 `user-ui/src/index.css` 的 `@media (max-width: 767px)` 中集中将多列指标条覆写为 2 列网格、为表格外层滚动容器开启 `overflow-x: auto`，并修正 `.set-row` 与 `.logrow .tgt` 的窄屏尺寸约束，避免逐页散落修改业务组件。

## 预期影响
- 手机端（320px–767px）访问 `/admin` 与 `/user` 时所有页面布局不溢出、指标清晰可读、表格可横向滑动、导航抽屉开合顺畅。
- 桌面端（`>=1024px`）与平板横屏（`>=768px`）的渲染结果、布局像素与交互体验保持 100% 不变。

## 风险
- **风险 1：手机端抽屉打开后窗口拉宽至桌面尺寸导致遮罩残留**
  - 应对：遮罩层与顶栏均添加 `md:hidden`，且侧边栏位移类使用 `max-md:` 前缀，在 `>=768px` 下自动失效。
- **风险 2：固定视口高度页面（`h-[calc(100vh-56px)]`）在手机端带顶栏时高度计算偏差**
  - 应对：在 `@media (max-width: 767px)` 下将固定高度容器降级为自适应最小高度或扣除移动端顶栏高度，确保内部滚动与页面滚动正常。
